# Network Risk evidence record

Status: reviewed

Question: what network and proxy configuration is visible to this application, which exact client packages are visible, and what module deployment metadata can this ordinary process actually read? These observations do not establish that any request used a proxy, attribute a core to a module, or establish that a device is compromised. Observed VPN/proxy configuration, exact client-package hits and valid module deployment traces are WARNING for review within their stated scope. Warning does not imply hostile activity.

## Ownership and applicability

- `domain`: typed observations, coverage states, client catalogue and signer policy; no Android types.
- `data`: ConnectivityManager adapter, packageinventory consumer and independent Box4Magisk / Box for Root metadata probes. No shell, root request, JNI, port scan or config traversal.
- `presentation`: shared card wording and explicit privacy export projection. `ui`: existing card frame, paired facts and collapsible section components. `detector`: the only composition boundary for App and headless SDK; catalogue registration is the only external touch point.
- Minimum API 29. Active network / process binding / default proxy require API 23, LinkProperties proxy/routes API 21, Private DNS API 28, current signing certificates API 28, typed PackageManager flags API 33 with an older overload below it. No hidden APIs.
- Implementation comparison: Android 10 `android-10.0.0_r1` and Android 15 `android-15.0.0_r1`; public API contracts govern later releases, including compile/target API 37. Later OEM/Mainline implementations and release changes have not been validated on devices. A missing/null property is retained, never promoted into a device-wide negative.
- A completed READY report preserves probe errors in its headline and SDK status. When no warning evidence is present, platform queries, read limits, malformed metadata, disappeared network properties and signing-read failures aggregate to INFO/ERROR with an incomplete verdict. Observed warning evidence takes precedence over unrelated errors, with incomplete coverage retained in the verdict, summary and detail rows. Permission limits, unsupported scope, changing samples, source differences and disabled active checks remain INFO/SUPPORT; available observations are retained.
- Every probe retains its own observation state: OBSERVED, NOT_OBSERVED, UNAVAILABLE, PERMISSION_LIMITED, UNSUPPORTED or INCONCLUSIVE. A permission denial is coverage loss; a platform/read failure is an error; neither means a clean result. Disabled active probes are unavailable coverage, not execution failures.

## Signals

### Caller default, process binding and visible VPN transport

- Observable signal: Calling UID's default Network, explicitly bound process Network, framework-visible network handles and transport capabilities.
- Producing subsystem: ConnectivityManager Binder client, ConnectivityService UID selection/access filtering and process-local NetworkUtils binding.
- Mechanism: `getActiveNetwork()` and `getBoundNetworkForProcess()` are separate observations. Read `getAllNetworks()`, include queried default/bound handles, then query each handle's capabilities and LinkProperties. More than 32 handles is an explicit collection-budget failure. No binding is changed. VPN transport on another visible handle is not equated with the caller's default or every socket.
- References: [Android ConnectivityManager](https://developer.android.com/reference/android/net/ConnectivityManager), [NetworkCapabilities](https://developer.android.com/reference/android/net/NetworkCapabilities); AOSP frameworks/base [Android 10 ConnectivityManager](https://android.googlesource.com/platform/frameworks/base/+/android-10.0.0_r1/core/java/android/net/ConnectivityManager.java) and [ConnectivityService](https://android.googlesource.com/platform/frameworks/base/+/android-10.0.0_r1/services/core/java/com/android/server/ConnectivityService.java); packages/modules/Connectivity [Android 15 ConnectivityManager](https://android.googlesource.com/platform/packages/modules/Connectivity/+/android-15.0.0_r1/framework/src/android/net/ConnectivityManager.java) (`getActiveNetwork`, `getBoundNetworkForProcess`) and [ConnectivityService](https://android.googlesource.com/platform/packages/modules/Connectivity/+/android-15.0.0_r1/service/src/com/android/server/ConnectivityService.java) (`getActiveNetworkForUidInternal`, `getVpnForUid`, `getDefaultNetworkForUid`).
- Applicability: API 29+ here; ACCESS_NETWORK_STATE is declared by the data module for both App and SDK hosts. All-network enumeration is deprecated from API 31 but still public; results are scoped to what that caller can observe.
- Visibility limits: Default selection is UID scoped. Blocked and disconnected default queries can both be null. Process binding does not describe explicitly Network-bound sockets or older sockets. App exclusions, work-profile VPNs and local filters can produce different views. No claim about all users or kernel policy routing.
- Result states: Non-null values OBSERVED; null default/binding NOT_OBSERVED in the stated scope; permission failure PERMISSION_LIMITED; API/service/read failure UNAVAILABLE; disappearing capabilities/links UNAVAILABLE; changed sample INCONCLUSIVE.
- Interpretation: Configuration/context only. Observed VPN transport in a repeated sample is WARNING in its transport row, header fact and headline. Enterprise VPN, ad filtering and legitimate privacy clients are ordinary explanations; the warning does not attribute a module or assert that this app uses that VPN. Default/bound handles and successful enumeration alone remain INFO.

### Interfaces, routes, proxy configuration, PAC and Private DNS

- Observable signal: Per-handle LinkProperties interface, route family/prefix/default/gateway-presence summaries, HTTP proxy type/port/exclusion count, Private DNS active/strict-name flags and DNS-server count; separately, default HTTP proxy configuration.
- Producing subsystem: ConnectivityService network LinkProperties, ProxyTracker global proxy and ConnectivityManager process binding.
- Mechanism: `getDefaultProxy()` calls `getProxyForNetwork(getBoundNetworkForProcess())`. The service chooses global proxy first, then the supplied bound handle if accessible, otherwise the calling UID's active network (the null-network path uses `ignoreBlocked=true`). This can legitimately differ from a blocked `getActiveNetwork()` result or a particular link's proxy. `getHttpProxy()` belongs to that link. A nonempty PAC URI identifies configuration only; no PAC script is fetched or evaluated. Private DNS is independently recorded.
- References: [Android ConnectivityManager.getDefaultProxy](https://developer.android.com/reference/android/net/ConnectivityManager#getDefaultProxy()), [LinkProperties](https://developer.android.com/reference/android/net/LinkProperties), [ProxyInfo](https://developer.android.com/reference/android/net/ProxyInfo); AOSP packages/modules/Connectivity [ConnectivityManager](https://android.googlesource.com/platform/packages/modules/Connectivity/+/android-15.0.0_r1/framework/src/android/net/ConnectivityManager.java) (`getDefaultProxy`), [ConnectivityService](https://android.googlesource.com/platform/packages/modules/Connectivity/+/android-15.0.0_r1/service/src/com/android/server/ConnectivityService.java) (`getProxyForNetwork`, `getLinkPropertiesProxyInfo`), [ProxyTracker](https://android.googlesource.com/platform/packages/modules/Connectivity/+/android-15.0.0_r1/service/src/com/android/server/connectivity/ProxyTracker.java) and [LinkProperties](https://android.googlesource.com/platform/packages/modules/Connectivity/+/android-15.0.0_r1/framework/src/android/net/LinkProperties.java). Android 10 counterparts above were also compared.
- Applicability: Link properties API 21+, default proxy API 23+, Private DNS API 28+, project minimum API 29. No procfs/netlink routing-table parser or kernel-wide inference is used.
- Visibility limits: Link routes are the framework's per-network view, not firewall marks, per-UID ip rules or the whole routing table. Apps may ignore proxy settings, bind sockets differently, use native protocols or hit PAC DIRECT/exclusion rules. Private DNS says nothing about a proxy or a particular library's DNS path.
- Result states: Proxy present OBSERVED, null NOT_OBSERVED for the query scope; inaccessible/vanished link UNAVAILABLE or PERMISSION_LIMITED. Private DNS false is NOT_OBSERVED for that link. Changes during repeated reads make configuration observations INCONCLUSIVE.
- Interpretation: Observed default HTTP, per-network HTTP/PAC or JVM HTTP proxy configuration in a repeated sample is WARNING; actual request use is unevaluated. Interface/routes and Private DNS remain INFO. Private DNS alone never counts as proxy evidence. No proxy host, URI, DNS name, DNS address, local address or gateway address is retained in the domain report. Interface names and ephemeral handles appear locally but are excluded from export.

### Scan-time network changes

- Observable signal: Equality or change in two adjacent complete raw framework samples, with monotonic duration and wall-clock sample start.
- Producing subsystem: Independent ConnectivityManager snapshots, which have no transactional multi-query API.
- Mechanism: Compare default/bound handles, default ProxyInfo, process-local JVM HTTP proxy values and every selected handle's NetworkCapabilities/LinkProperties and failure state. Retry the entire pair once on differences (at most four complete reads). Raw values are discarded after comparison and reduced to the privacy projection. A changed second pair retains only the last sample and marks its positive and negative network observations INCONCLUSIVE. No contradiction rule exists.
- References: [Android network state guide](https://developer.android.com/develop/connectivity/network-ops/reading-network-state), [NetworkCallback](https://developer.android.com/reference/android/net/ConnectivityManager.NetworkCallback); AOSP packages/modules/Connectivity ConnectivityManager and ConnectivityService methods linked above establish separate synchronous Binder reads, not atomic snapshots.
- Applicability: All supported APIs. No callback registration, background listener or implicit callback lifecycle is introduced. Binder calls have no application-enforced hard timeout; the count is bounded, not their kernel/service latency.
- Visibility limits: Equal adjacent reads cannot exclude ABA transitions, changes immediately afterward or changes in actual packet routing. Timestamp is a sampling window, not a claim of simultaneous values. Package and module probes are separate observations and are never correlated into network inconsistencies.
- Result states: Repeated sample OBSERVED consistency with limited scope; persistent change INCONCLUSIVE; individual query failures retain their own states.
- Interpretation: No observations from different retries are merged into an alleged contradictory state.

### Framework / JVM HTTP proxy cross-check

- Observable signal: Default ProxyInfo and fresh process-local `http.proxyHost` / `http.proxyPort` values, observed inside the same repeated-sampling window.
- Producing subsystem: ConnectivityService's default proxy, ActivityThread proxy updates, android.net.Proxy's JVM-property synchronization, and libcore's java.lang.System Properties object.
- Mechanism: Reuse the JVM reader extracted from capability/systemproperties; its existing consumer retains the same trim/empty fallback, while networkrisk preserves null versus read failure. Compare static HTTP host (case-insensitive textual equality, without DNS resolution) and numeric port. Both absent or equal endpoints align; different views remain INCONCLUSIVE. A partial/out-of-range JVM pair is INCONCLUSIVE. PAC is explicitly not comparable to a static endpoint. Raw host values participate in adjacent sample equality but are discarded before report projection; only JVM state/port and the typed comparison result survive.
- References: [Android System.getProperty](https://developer.android.com/reference/java/lang/System#getProperty(java.lang.String)), [ConnectivityManager.getDefaultProxy](https://developer.android.com/reference/android/net/ConnectivityManager#getDefaultProxy()), [ProxyInfo](https://developer.android.com/reference/android/net/ProxyInfo); AOSP frameworks/base [Android 10 Proxy.setHttpProxySystemProperty](https://android.googlesource.com/platform/frameworks/base/+/android-10.0.0_r1/core/java/android/net/Proxy.java), [Android 15 Proxy.setHttpProxyConfiguration](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/core/java/android/net/Proxy.java), [ActivityThread.updateHttpProxy](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/core/java/android/app/ActivityThread.java), packages/modules/Connectivity [ConnectivityManager.bindProcessToNetwork](https://android.googlesource.com/platform/packages/modules/Connectivity/+/android-15.0.0_r1/framework/src/android/net/ConnectivityManager.java), and libcore [System.getProperty / setProperty](https://android.googlesource.com/platform/libcore/+/android-15.0.0_r1/ojluni/src/main/java/java/lang/System.java).
- Applicability: Project API 29+; JVM property reads are public API 1. Reviewed Android 10 and 15 synchronization paths. No reflective framework call, getprop process, native property probe or traffic request is added.
- Visibility limits: Java system properties are a process-local namespace, distinct from Android's Bionic/init property service. The two views are correlated because framework code writes the JVM view; they are not independent trust anchors. Application overrides, asynchronous updates and process binding changes can produce legitimate differences. A custom ProxySelector, per-request overrides, exclusion lists, HTTPS/SOCKS settings and PAC decisions are outside this static HTTP host/port comparison.
- Result states: JVM absent NOT_OBSERVED, complete pair OBSERVED, partial/invalid pair INCONCLUSIVE, denied read PERMISSION_LIMITED and read failure UNAVAILABLE. Comparison aligns, differs (INCONCLUSIVE), skips PAC (UNSUPPORTED scope), or lacks comparable sources (INCONCLUSIVE). A changed sample invalidates any apparent agreement. The cross-check row remains INFO because a difference is inconclusive; a complete observed JVM proxy pair independently receives WARNING only when sampling repeats.
- Interpretation: Reports agreement or difference between two scoped configuration views; neither agreement nor difference establishes proxy use, a hook, a module or compromise. No default proxy, JVM property or selector is modified by collection.

### Exact client packages and signer identity

- Observable signal: Exact catalogue package in the calling user's packageinventory result, installed version code and current signer certificate set.
- Producing subsystem: PackageManager application visibility and SigningInfo.
- Mechanism: Reuse capability/packageinventory; no label or app-name substring match. Request exact `<queries>` in the data manifest. For visible matches, read GET_SIGNING_CERTIFICATES and SHA-256 each current certificate. Signature verification requires the entire current signer set to equal the one pinned release key. Past signing history, unknown keys, missing certificate reads and extra signers never pass. Repackaged, store-specific and future rotated-key builds can remain identity-unverified.
- References: [Android package visibility](https://developer.android.com/training/package-visibility), [SigningInfo](https://developer.android.com/reference/android/content/pm/SigningInfo), [PackageManager](https://developer.android.com/reference/android/content/pm/PackageManager); AOSP frameworks/base [AppsFilterImpl](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/services/core/java/com/android/server/pm/AppsFilterImpl.java), [ComputerEngine](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/services/core/java/com/android/server/pm/ComputerEngine.java); [packageinventory evidence](../../capability/packageinventory/EVIDENCE.md). Upstream artifacts and reproducible signer extraction are recorded below.
- Applicability: API 29+, visibility filtering for target/API 30+; typed flags on API 33+. Fused SDK manifest includes the same exact queries. No QUERY_ALL_PACKAGES permission is added by this feature.
- Visibility limits: Calling user/profile only; other users, work profiles, disabled profile state and packages hidden from the inventory are outside coverage. Full/restricted/unknown visibility is reported. A package disappearing between inventory and signature query becomes INCONCLUSIVE. Inventory absence is only NOT_OBSERVED, never "uninstalled".
- Result states: Exact package hit OBSERVED, package not returned NOT_OBSERVED in inventory scope; inventory failure UNAVAILABLE. Identity separately SIGNATURE_VERIFIED or IDENTITY_UNVERIFIED with signing-read state; permission errors remain PERMISSION_LIMITED.
- Interpretation: An observed exact client-package match is WARNING, whether signature verified or identity unverified. A signing-read failure cannot erase package presence; its failure detail remains visible. The header client count warns only for positive hits, not for successful empty inventory. Package-name match, signing-key verification and service activity are distinct claims. Installation cannot establish service activity, active rules or any traffic effect. Pins describe the sampled GitHub release channel, not all stores/forks or every historical version.

### Box4Magisk and Box for Root deployment metadata

- Observable signal: Bounded regular-file read of `/data/adb/modules/box4/module.prop` or `/data/adb/modules/box_for_root/module.prop`, matching exact `id` plus a single printable version field.
- Producing subsystem: Root manager module deployment layout, Android file access controls and upstream module metadata.
- Mechanism: Independent feature-owned collectors share only bounded metadata reading. `Os.open` uses O_NOFOLLOW, O_NONBLOCK and O_CLOEXEC; fstat must be regular; read limit 4096 bytes. Preserve errno; EACCES/EPERM becomes PERMISSION_LIMITED; ENOENT/ENOTDIR only means this exact path was not observed. No shell, symlink following at the final component, module configuration, subscriptions or process enumeration.
- References: [Android Os](https://developer.android.com/reference/android/system/Os), [Android SELinux](https://source.android.com/docs/security/features/selinux), AOSP system/sepolicy [Android 15 file_contexts](https://android.googlesource.com/platform/system/sepolicy/+/android-15.0.0_r1/private/file_contexts) (`/data/adb` is adb_data_file), [libcore Linux JNI](https://android.googlesource.com/platform/libcore/+/android-15.0.0_r1/luni/src/main/native/libcore_io_Linux.cpp), [Bionic open](https://android.googlesource.com/platform/bionic/+/android-15.0.0_r1/libc/bionic/open.cpp), [ACK android15-6.6 namei](https://android.googlesource.com/kernel/common/+/refs/heads/android15-6.6/fs/namei.c); upstream deployment metadata and scripts in the matrix below.
- Applicability: Known module IDs/paths at the pinned upstream revisions only. Android sandbox policy, root-manager overlay mounts and OEM policy determine actual visibility. ACK source explains access-error propagation; no tested-device kernel revision or universal visibility guarantee is claimed.
- Visibility limits: Commonly inaccessible under ordinary permissions; inaccessible parent directories conceal both existing and missing children. Different install roots, renamed modules, overlay state and modified metadata escape or spoof these probes. No privileged directory listing, firewall rules, process state or logs are available. No cross-feature dependency on mount detection is introduced.
- Result states: Exact readable metadata OBSERVED deployment trace; denied PERMISSION_LIMITED; path absent NOT_OBSERVED within exact-path scope; malformed/duplicate/mismatched metadata INCONCLUSIVE; I/O or budget failure UNAVAILABLE. Service response and traffic effect separately UNAVAILABLE because not probed.
- Interpretation: WARNING for an exact readable deployment trace only, with unauthenticated metadata explicitly stated. Denied, missing, malformed or unreadable metadata never receives warning. The proxy core and actual REDIRECT/TPROXY/TUN mechanism remain unknown. Shared `/data/adb/box` paths, port numbers and TUN names are deliberately not attributed to either project.

## Severity policy

`domain` owns report aggregation and the shared VPN observation rule. Presentation raises only rows describing observed VPN/proxy configuration, exact client packages or valid deployment metadata; successful queries, visibility, scan consistency and privacy facts stay INFO. Network warnings require a REPEATED window. CHANGED windows retain INCONCLUSIVE network rows and cannot warn from their last snapshot; independent package/module warnings still survive. Local configuration warnings neither authenticate a service nor establish traffic routing. Source differences, ordinary network binding, routes, Private DNS, denied access and disabled active tests remain informational. The references above establish observable semantics; warning is a review policy rather than a platform security guarantee. Collection, retry budgets and privacy projection are unchanged.

## Active-check research and privacy boundary

Active probes remain disabled and unimplemented in this PR: zero endpoints, zero requests, zero payload bytes, no PAC download, no local port scan; timeout is not applicable. A future opt-in needs explicit UI/SDK configuration of endpoint, protocol, destination literal/domain, exact bytes, per-request/total timeout, request cap and byte budget before any request is sent. A positive control plus device ground truth is required before interpreting a traffic difference.

Research candidates only:

| Candidate | Protocol and sample record required | Counterexamples / interpretation |
|---|---|---|
| DNS consistency | Exact DNS/DoT/DoH protocol, resolver address/domain, query type/name, A/AAAA response and timestamp; respect active Private DNS. | Split DNS, caching, DNS64/NAT64, enterprise policy, portals and ad filtering can differ legitimately. |
| Egress consistency | Explicit HTTPS endpoint, controlled response/body, chosen Network/socket path, destination family and timestamp. | NAT, carrier gateways, enterprise gateways, load balancing and dual-stack exits are not module evidence. |
| Local protocol response | User-selected loopback address/port and minimal specified HTTP/SOCKS handshake with strict bounds; no credential guessing or proxy CONNECT to third parties. | Open TCP alone, protocol response, authentication refusal, connection refusal, timeout and parse failure must remain distinct. Ports can change and control APIs may be disabled; no module attribution follows. |

No endpoint is chosen implicitly. A service response would establish only a responding service. A specific flow's effect requires a controlled test tied to its network, protocol, address family and time plus rules/logs; it cannot be inferred from a module path or package. Shared mount evidence, if later correlated, must enter at a composition boundary through a capability rather than a feature dependency.

### Controlled VPN and offline coverage

The test APK includes an opt-in, test-only `VpnService` fixture. Its owner keeps and closes a local TUN descriptor through an explicit bound control connection; no socket, packet forwarding, remote server or DNS query is implemented. The fixture manifest and its INTERNET permission are confined to androidTest. The production collector still changes no network binding and sends no requests.

The fixture follows the public [VpnService](https://developer.android.com/reference/android/net/VpnService) contract and the release-matched Android 15 [VpnService.Builder](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/core/java/android/net/VpnService.java) (`addAllowedApplication`, `allowBypass`, `setHttpProxy`, `establish`) and [Vpn](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/services/core/java/com/android/server/connectivity/Vpn.java) implementations (authorization, per-UID ranges and descriptor lifecycle). PAC is not supported over VpnService; its additional runtime test constructs a ProxyInfo and checks the privacy projection/comparison without installing a PAC configuration or fetching a script.

These are operating-system VPN fixtures, not enterprise VPN, third-party client or transparent-proxy module acceptance.
